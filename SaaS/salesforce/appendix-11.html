附录 11 · Atlas 推理引擎技术解析：六步循环

📌 核心观点
推 1 · Atlas 定位

Atlas Reasoning Engine 不是「Salesforce 里的 ChatGPT」。

是多模型推理系统，决定智能体做什么、什么顺序、用什么信息。

在用户请求和可调用工具之间的规划和执行层。

推 2 · 六步循环①理解意图

步骤1 理解意图：解析用户输入确定请求类型。

不是关键词匹配，而是从对话历史解释上下文。

映射到可用的 agent topics，定义智能体被允许的范围。

推 3 · 六步循环②RAG检索

步骤2 RAG 检索上下文：向 Data Cloud 发出检索查询。

拉取最相关的客户记录、案例历史、产品目录到推理窗口。

这是区分 grounded 响应和幻觉的关键——读取真实记录而非训练数据。

推 4 · 六步循环③④规划执行

步骤3 规划行动序列：构建计划——调用哪些 actions、什么顺序、什么参数。

步骤4 执行行动：调用 Salesforce 记录操作、Flows、Apex、外部 API 或 MuleSoft。

每个行动返回结果，引擎在决定下一步前纳入结果。

推 5 · 六步循环⑤⑥验证响应

步骤5 验证输出：检查输出是否与意图和上下文一致。

不一致则重新规划和执行额外步骤。

步骤6 响应：最终输出返回用户，完整推理轨迹通过 Trust Layer 记录。

推 6 · Trust Layer

Einstein Trust Layer 包裹每个请求和响应。

Mask PII、扫描毒性和提示注入、执行零数据保留协议。

记录每个操作供审计。数据不离开 Salesforce 基础设施。

推 7 · 架构优势

与独立 AI 工具的最大架构优势：不需要单独集成层。

Agent 操作是原生 Salesforce 操作。

自动应用共享规则、验证规则和触发器——继承用户权限。

推 8 · Data Cloud grounding

Data Cloud 作为 grounding 层。

统一来自 org 和外部源的数据到单一可查询 CDP。

没有 Data Cloud，跨实体上下文缺失——VIP 和流失风险小账户得到相同通用答案。
