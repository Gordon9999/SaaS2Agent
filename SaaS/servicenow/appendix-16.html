AI Control Tower 技术深度：五维治理

来源：NowSpectrum · 2026年
📌核心观点
推1

AI Control Tower 是 ServiceNow 环境中每个 AI agent、模型和工作流的治理层——越来越多也涵盖外部 agent。

核心问题是企业部署 AI agent 的速度快于治理能力，数百个 agent 在断开系统中运行，没有统一视图。

推2

五维治理框架构成完整的 AI agent 生命周期管理能力：Discover 发现、Govern 治理、Observe 观察、Secure 安全、Measure 度量。

每一维解决一个核心痛点——从资产可见性到权限控制，从行为监控到身份安全，再到投资回报度量。

推3

KN26 演示了一个被入侵的 agent 通过 prompt injection 操纵，开始未授权定价更改。

AI Control Tower 实时检测异常行为，撤销 agent 权限，数秒内关闭。这是治理层在真实攻击场景下的价值证明。

👤访谈人背景
推4

本文未涉及该维度。

💬行业
推5

企业部署 AI agent 的速度快于治理能力，这是一个行业性问题。数百个 agent 在断开系统中运行，没有统一视图。

95%的组织目前无法度量 AI 投资的业务价值，这意味着绝大多数企业的 AI 支出是盲目的。

推6

AI agent 生命周期管理成为新的运营责任——管理 agent 身份、策略和权限，就像管理用户账户、角色和组一样。

这是企业 IT 治理的新范式，管理员需要从"管人"扩展到"管 agent"。

📦公司
推7

ServiceNow 将 AI Control Tower 定位为跨环境统一治理层，不仅治理 ServiceNow 自有 agent，也通过 Action Fabric 和30+企业集成治理第三方 agent。

这使 ServiceNow 从工作流平台升级为企业 AI 治理中枢。

推8

Microsoft 合作是最清晰的合作案例——Copilot Studio agent、Azure Foundry agent 和 ServiceNow AI Specialist 在同一治理层下运行。

这意味着企业可以用一个治理平面管理来自多个生态的 AI agent，开创跨平台 AI 治理先例。

🧩产品
推9

Discover（发现）能力自动识别全企业所有 AI 资产——ServiceNow agent、第三方 agent、AI 模型和工作流。

所有数据馈入 CMDB，建立 AI 资产的单一事实来源。没有发现，就没有治理。

推10

Govern（治理）为每个 agent 设置策略、权限和护栏。定义允许行动、可访问系统、可代表用户、升级路径。

关键优势是策略定义一次，跨所有 agent 一致执行，避免治理碎片化。

推11

Observe（观察）实时监控 agent 行为和运行时活动。每次 API 调用、记录更新、工作流触发、审批被记录和可观察。

异常检测标记偏离预期模式的行为，在问题扩大前发出预警。

推12

Secure（安全）将 AI agent 视为有权限、访问权和问责制的身份。集成 Veza 访问图技术，映射超300亿条权限记录。

Armis 收购进一步扩展到 IT、OT、IoT 和医疗设备，覆盖企业全资产面。

推13

Measure（度量）跟踪 AI 投资的业务价值——解决率、时间节省、成本影响、ROI。

95%的组织目前无法度量这一点，AI Control Tower 填补了 AI 投资回报的度量盲区。

推14

通过 Action Fabric 和30+企业集成，可发现、观察和治理在其他环境中运行的 agent。

这使跨平台 agent 治理成为现实，企业不再被锁定在单一 AI 生态中。

🏗️组织
推15

对管理员的意义——AI agent 生命周期管理成为新运营责任。

管理 agent 身份、策略和权限，就像管理用户账户、角色和组一样。IT 团队的职责边界正在扩展。

推16

第三方 agent 治理通过 Action Fabric 实现，Microsoft 合作最清晰。

Copilot Studio agent、Azure Foundry agent 和 ServiceNow AI Specialist 在同一治理层下运行，开创跨平台 AI 治理先例。

组织需要建立跨生态的 AI 治理能力，而非仅限于单一平台内部。
