📌 核心观点
推 1 · 六层架构

Agentforce 六层架构：

① 渠道层：Slack/聊天/SMS/Voice

② Agentforce 层：Atlas + Agent Builder

③ 信任层：Einstein Trust Layer

④ 模型层：Salesforce 调优 + 外部 LLM

⑤ 数据层：CRM + 知识库 + Data Cloud

⑥ 平台层：Flows/Apex/REST API

🧩 产品
推 2 · 渠道层

同一智能体可在任何渠道运行：Slack、Experience Cloud、Lightning UI、嵌入式聊天、邮件、SMS、Voice。

Agentforce Voice 通过 Amazon Connect、Five9、Genesys 等 IVR 合作伙伴实现。

渠道无关架构让智能体部署灵活性大幅提升。

推 3 · Atlas 处理流程

Atlas 处理一次请求的完整流程：

上下文组装 → 主题分类 → 计划生成 → 行动执行 → 响应生成 → 护栏检查

整个过程通常 2-5秒 完成。

推 4 · 模型层

Model Builder 允许连接外部 LLM：OpenAI、Anthropic、Azure OpenAI、Google Vertex AI。

默认 Salesforce 调优模型不满足特定领域需求时使用。

企业数据驻留要求强制特定云提供商时也可用。

推 5 · 数据 grounding 三层

① CRM 记录 grounding：查询 Salesforce 对象获取实时数据

② 知识库 grounding：Salesforce Knowledge 文章通过向量搜索

③ Data Cloud grounding：统一客户档案，结合 CRM + 外部源

没有 grounding，智能体只能基于对话内容推理。

推 7 · 常见架构错误

① topics 太多：增加分类复杂度，应从少而宽开始

② actions 描述模糊：LLM 按描述选择 action，需像 API 文档一样精确

③ agent 权限过大：应给最小必要权限

④ 没有 fallback topic：范围外请求会产生不可预测行为

⑤ 知识文章过时：矛盾文章是幻觉最常见原因
