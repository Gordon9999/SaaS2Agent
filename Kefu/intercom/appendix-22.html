Fin × Snowflake: Deploying Agentic AI in the Enterprise

来源：Intercom 旧金山线下活动（2026 年 3 月）· Jordan Neil（Intercom COO）× Barish（Snowflake AI 产品负责人）

📌 一句话总结
推 1 · 核心结论

「企业级 Agentic AI 部署」对谈：技术 overhang 巨大——平均 Fin 客户 67% 解决率、Intercom 自己 80-85%，但多数企业还在用老一代 30% 解决率甚至完全没用——「采用远远落后于能力」，瓶颈不是构建而是习惯与组织转型（CEO 发邮件没用，需要资深领导深刻理解 + 全组织再造）。

方法论共识：①eval 是核心引擎（Snowflake：自动 eval 循环「agents building other agents」；Intercom：eval 必需但无法替代真实世界——Waymo 停电停满街）；②上下文是关键（模型越强，瓶颈越是共享理解）；③自研模型：新东西先用最强 frontier 模型，再对「智能已饱和」任务做 task-specific 优化；④信任与治理是前提：「AI next to data」（inference 在 Snowflake 安全边界内 = 巨大优势）。

👤 访谈人背景
推 2 · 录制信息

录制时间/地点：2026 年 3 月，旧金山（线下活动 + Q&A）；时长约 47 分钟。

主持：Jordan Neil（Intercom COO，过去两年专注 Fin）；嘉宾：Barish（Snowflake Head of Product for AI，创业公司 2.5 年前被收购并入成 AI 团队，CEO 即前 co-founder、极度 AI forward）。

推 3 · 素材定位

第三场「Fin × 知名公司」活动对谈（继 ×Linear、×PostHog），视角：企业级部署 + 自研模型策略 + 信任/治理/eval。

与前篇互证：eval/自动化循环（呼应 16/20 篇）、自研模型（呼应第 7 篇 CX Apex）、结果导向定价（呼应 13/19/21 篇）。

💬 行业
推 4 · 技术 overhang：采用远落后于能力

「未来已来，只是分布不均」：Fin 平均客户 67% 解决率、Intercom 自己 80-85%——但多数公司根本没用或还在用老一代（30% 解决率还觉得干得不错）——「技术坐在那里等他们」。

企业心态轨迹：恐惧（数据怎么办/AI 治理委员会）→ POC 探索 → 过去几个月「紧迫感」：「这必须是核心，人人参与 AI，否则被落下」——已有生产系统、看到真实 ROI。

为何还不是每家都在用：「习惯」——CEO 发邮件没用，人们发一个 query 就回到老做法；最快路径是资深领导深刻理解可能 + 全组织一起转型。

新购买心智：从「买软件帮人做客服」到「买软件直接做客服」——别问「软件预算」，要看「客服 TCO」；类似 2000 年代 SaaS 转型。

📦 公司
推 5 · Snowflake 的 AI 转型

旅程：2.5 年前收购并入成 AI 团队，zero to one；CEO「活在 AI 里」，同时驱动开发 AI 与全组织采用 AI；「不断去够能力的极限，因为它很快就可能」。

产品：Cortex Code（数据向 coding agent：建管道、建 agents）；Snowflake Intelligence（业务用户建 agent，必须准确——「问纽约收入必须精确答案，零容错」）。

内部应用：sales agent 部署给 6000 名销售（book of business/消费走向/竞品分析，连 10+ 数据源）；营销负责人给自己建「PRD → 博客/新闻稿」agent——「角色已经失去意义，而且会继续」；无编码销售用 coding agent 10-20 分钟建 anomaly detector。

推 6 · 为什么两家都自研模型

与 OpenAI/Anthropic 深合作（推理等 frontier 能力用他们的），但任务特定场景自研——Snowflake：分类/情感/转录/翻译高吞吐函数、文档提取、自研 embedding（Neva 搜索团队遗产）；Intercom：reranker/retrieval/summarization——retrieval 模型的 base 竟是 Snowflake 开源模型 Arctic，领域微调后同成本同延迟大幅提升。

决策框架：新东西先用最强大模型搞清楚再优化；很多任务「智能已饱和」——最新模型「overpowered」，task-specific 后训练性能/延迟/成本三赢。

🧩 产品
推 7 · 质量：不同 agent 不同标准

建 agent 容易（冰山问题：demo 容易、真实世界 messy；「周末 vibe code 原型 vs 规模化可靠」差距巨大）——质量标准因类型而异：内部工具（专家 reviewer 容错高）vs Fin（面对非专家客户：必须极准、不编造、知道何时不回答） vs Cortex Analyst（结构化数据零容错）。

单公司内部 agent vs 服务任意公司：不同 schema/semantic layer——「可靠处理任何东西」更难（Fin 8000 客户 vs bespoke per company：改善一家不惠及他人）。

推 8 · eval 与真实世界信号

Snowflake：test harness + 自动生成 eval 数据集 → 自动优化 → 自动迭代——「agents building other agents」；隐私考量下用thumbs up/down → agent owner，agent memory 跨用户学习向 admin 建议改进。

Intercom 反直觉观点：eval 必不可少（内部循环引擎），但无法替代真实世界——Waymo 旧金山停电全停街中（「没建这个 eval」）；Fin 靠 8000 客户每周数百万对话获信号，用户会告诉你是否解决 + 公司有利益纠偏。

人类时间未来：手动 query → steer/govern/monitor agents → 最终连最终行动也自动化；「agent 改善 agent 的自主循环将远超人类可能」——但要配 guard rails。

推 9 · 构建 Agent 是垂直集成栈

客户配置 × harness 层 × 模型——三者紧密耦合：换模型/harness/术语全变；「升级新 Sonnet 一定更好」是假象——没调 prompt 可能反而 underperform（有 eval 才能发现）。

最难问题：Fin 配置由客户编写——产品迭代必须resilient：不意外破坏 8000 客户配置、不让客户持续改 prompt；tone-of-voice 等配置要经「编译/插值步骤」翻译（海盗物流客户 Pirate Ship 例子）；AI 工具帮客户识别矛盾 guidance。

可靠性：「退款 20% → 2000%」类灾难——人类也会犯错，但没人质疑人类、人人质疑 agent；多步流程是硬前线：10 步 × 每步 95% 可靠 = 整体 ~50%（没用）；解法：自然语言流程里混入确定性逻辑（直接写 Python，Fin 按代码执行）。

🏗️ 组织
推 10 · 信任与治理是采用前提

信任 = 答案准确 + 安全治理；Intercom：ISO/HIPAA + AI1 认证（专为 AI agent 的 ISO 式认证、第三方红队测试 Fin）——「客户不必只信我们一面之词」。

Snowflake 核心设计原则：「把 AI 带到数据旁边，而不是把数据带出来给 AI」——安全边界内运行、访问控制全被尊重；Intercom 用 Snowflake 跑 AI 时inference 发生在 Snowflake 安全边界内 = 巨大竞争优势。

能力 vs 安全：「没有 trade-off，安全/治理不可妥协」（作为平台能力提供）；受监管行业客户要能描述 guard rails 并信任 Fin 遵守——让客户写 eval simulation tests（Fin 扮演用户/扮演自己/评判/给反馈，四个 AI 角色）。

推 11 · Build vs Buy 与创始人忠告

答案「both」：在平台上构建（不必 reinvent wheel）+ 「外包非差异化重活，全力投入差异化领域专长」；两家互相是客户（Snowflake 用 Fin、Intercom 用 Snowflake）。

构建时间下降：高质量 sales agent 3 个月，CEO 挑战「3 个月 → 3 天」（Cortex Code 把 agent 创建/优化做成核心能力）；但构建不是瓶颈，采用才是。

创始人两难：「正确的回应是偏执——只有偏执狂才能生存」（做边缘差异化 + 深领域专长）；但选的问题要大到能独立存活——可一旦够大，Anthropic/OpenAI 也会在意——「棘手的处境」。平台生态：「你们成功，我们就成功」。

💡 变现与叙事
推 12 · 变现与叙事

Snowflake：全部 consumption based（AI 同样）——「只为用掉的付费」；叙事升级：「data cloud → AI data cloud」——AI 让更多数据可被利用、洞察被民主化。

Fin：outcome based——解决才收费，对齐 Intercom × 客户激励；甚至对齐内部：销售团队已按「好的 Fin 配置」计酬（vs 坐席时代「卖掉坐席就完事」）；副作用：token 用量波动被封装进「一个解决单位 = 一个价」——波动是我们的问题，不是客户的问题。
