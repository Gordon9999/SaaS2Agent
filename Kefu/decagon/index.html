📌 核心观点
推 1 · 核心观点

Decagon 用两年多时间从零到 45 亿美元估值，把 90% 的 Agent 工作流迁移到开源微调模型上——不是因为便宜，而是为了语音 Agent 的延迟。

公司真正的定位不是「做好客服的 Agent」，而是「执行业务流程的 Agent」，终极愿景是成为企业客户交互的 AI 前门（concierge）。

🏢 主题简介
推 2 · 素材构成

本报告综合提炼自 12 篇素材：4 篇创始人深度访谈（a16z、No Priors、Upstart 等）、1 篇创始人对谈（Julia Hartz × Ashwin Sreenivas）与 7 篇官方产品/文化内容。

素材来源覆盖银行、航空、电信等企业客户视角与 Decagon 内部视角，从不同侧面交叉印证公司战略与产品能力。

推 3 · Decagon 是谁

Decagon 是面向大型企业的 AI 客服公司，由 Jesse Zhang 与 Ashwin Sreenivas 于约三年前创立，D 轮融资 2.5 亿美元、估值 45 亿美元。

它与 Sierra 一起被认为是这个赛道的双雄，访谈中也透露其最新客户正是从 Sierra 转投而来。

推 4 · 典型客户案例

Decagon 的客户横跨科技、出行与零售：Eventbrite 续约数年、Duolingo、Avis、Fanatics、Hertz 与多家全球顶级银行、航空、电信企业。

早期客户 Vanta 帮助验证产品；Hertz 主动触达让未归还车辆减少 25%；某客户「我要真人」比例从 1/3 降到 1/20。

📦 公司战略
推 5 · 定位：从客服 Agent 到 AI 管家

Decagon 的愿景是：AI Agent 应该成为企业的前门，所有客户交互——无论被动还是主动——都由 AI 处理。

客服只是最早成熟的业务流程，之后会延伸到销售、运营与主动服务，他们称之为 AI 管家（concierge），未来可能是替代 App/网站的新 UI。

推 6 · 竞争格局：玻璃盒 vs 黑盒

与 Sierra 的对比是访谈的隐藏主线：客户在 Sierra 一年只建了 3 条新旅程，转投 Decagon 后一个月内建了 7 条。

Decagon 强调「玻璃盒」而非「黑盒」——客户自己可控、可快速迭代，而不是被 FDE 绑定、事事要过前线工程师。

推 7 · 护城河：10x 壁垒与应用层深度

要让满意的客户替换产品，后来者必须好 10 倍——Decagon 的 10x 来自 GenAI 原生：对手即便「贴」上 LLM，也被旧产品与既有客户拖累。

越企业级软件层越厚：对话可观测性、学习、洞察、测试仿真套件——「厚软件层 + 白手套交付」让大厂难以直接侵入。

推 8 · 融资与团队

公司由 a16z 投资，D 轮 2.5 亿美元；养了一支昂贵的 Decagon Labs 研究团队专职微调开源模型，80%+ 流量跑在自研模型上。

前 VMware CEO Raghu Raghuram 加入帮助国际化；「Decagon」这个名字由 Jesse 的妻子所起——十边形，寓意 10x 员工。

推 9 · 商业模式：从按席位到按对话

Decagon 采用按对话计费（conversation-based pricing）：客户购买对话额度随期间消耗，而非按席位或通话分钟。

对话是 Agent 可衡量的「有形产出」；这对应 AI 从 SaaS 走向「劳动/认知即服务」的大趋势，服务 TAM 并入软件市场。

🧩 产品战略
推 10 · 演化路径：从核心 Agent 到 Agent 工厂

第一阶段是核心客服 Agent，团队花 1-2 年打磨，人工编写 AOPs、工具与测试。

第二阶段推出语音 Agent，延迟压力推动 90% 工作流迁到开源微调模型；随后 AOPs 产品化，再演进到 Duet 与 Duet Autopilot，Decagon Labs 成为「模型工厂」。

推 11 · 产品矩阵：AOPs + Duet + Autopilot + Simulations

AOPs（Agent Operating Procedures）用自然语言而非代码编写业务流程，是业务逻辑与模型解耦的关键。

Duet 是构建 Agent 的 Agent；Duet Autopilot 回顾百万对话做模型变体实验；Simulations 是自维护的黄金测试集，为自我改进闭环铺路。

推 12 · 技术栈分层：开源为主、前沿为辅

90% 工作流运行在微调的开源小模型上，主要为语音 Agent 优化延迟；剩余 10% 用前沿模型处理新项目与开放式探索任务（如 Autopilot）。

每个模型沿 成本、智能、延迟 三个维度评估，用例固化后开源模型严格更优。

推 13 · 核心能力：小模型反而更强

Decagon 的核心洞察是：微调的小模型在特定任务上能同时做到更准、更快、更便宜——三项兼得，而非牺牲智能换成本。

专用小模型各司其职（检测用户说完、选正确 AOP、抓幻觉），共同支撑客服对话的完整流程。

推 14 · 数据流与评测：客户成果导向

模型评测不只看 loss 曲线，而是端到端衡量整个系统是否交付了客户要的成果；研究栈包括标注流水线、端到端评估与训练平台。

与用例强耦合的训练与评估基础设施自建，标注数据等通用任务外购。

🏗️ 组织文化
推 15 · 组织演化：从创始团队到规模化

Decagon 从创始期的 FDE + Agent PM 小团队起步，随客户增长快速扩张——销售总监 Grant 以创始期 GTM 首批员工身份加入，从一线销售做到销售领导。

如今接近 200 人，正在建立 people function 与更多组织结构；从「野兽型个体」走向「流程 + 结构」，办公室从旧金山扩展到纽约与欧洲。

推 16 · 团队：FDE 吃痛点，产出产品

Decagon 的 FDE（前线部署工程师）与 Agent PM 直接构建核心产品，而不是做一次性定制——产出回流产品，让接下来 10 个客户免费获得。

内部有句话：前线部署工程师「吃下痛点，产出产品」；一切围绕「能否产品化」评估，否则就会变成现代版埃森哲。

推 17 · 文化：团队运动，不设部门墙

工程师会上早期销售电话，销售会调试产品，APM 横跨两端——办公室文化是为了最大化沟通，不强制周末出勤。

新员工入职先到旧金山总部浸泡几周，新办公室由核心 hub 派人驻扎数月，直到形成自己的 Decagon 文化；招聘先选「聪明」而非直接经验。

推 18 · 客户案例：从 3 条到 7 条

转投案例验证了产品化路线：同一客户在 Sierra 一年建 3 条旅程，转投后一个月建 7 条。

另一早期客户月工单约 5 万条，把支持入口放到每个页面、向免费用户开放后，释放了被压抑的客服需求（Jevons 悖论）。

推 19 · 战略执行：速度、强度与客户第一

Decagon 的三支柱是工程速度、商业化、果断性——「不可能没有强度就建成大公司」，scramble 文化贯穿每周。

创始人把约 80% 时间花在销售上；PMF 三四个月就显现，当前最大瓶颈不是模型而是招人。

推 20 · 未来：concierge 与 Agent 生态

concierge 是从反应式支持走向购买决策、向上销售、主动触达的全新对话 UI——像 web→移动一样开启新交互时代。

未来会出现「Agent 与 Agent 对话」（如个人助理帮改签航班）；短期仍以自然语言为根基，因为每个 Agent 都要兼容人类。
